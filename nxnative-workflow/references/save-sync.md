# 配置存档同步与独立验收

入口：`$nxnative-workflow 配置存档同步`。本次已编译 Save Sync 宿主，但尚无真实双设备 iCloud 往返、冲突与回滚的完整验收记录；不得因整体游戏流程跑通就勾选同步通过。

先确认用户目标是存档同步。SideStore 配对/续签另见 [安装后配置](sidestore-setup.md)。

## 配置与首次测试

1. 两台设备均安装包含 Save Sync 的宿主，保留原宿主身份与已有数据；确认设置中有 Save Sync，游戏版本和 bundle ID 一致。
2. 为两边现有进度保留备份，先使用可丢弃的测试存档。正常保存并退出游戏，返回容器主界面后同步，避免覆盖正在运行的进度。
3. 在 iCloud Drive 创建用于本次测试的文件夹。两台设备使用同一 iCloud 账号，并各自通过 **Settings → Save Sync → Choose iCloud Drive Folder** 授权同一个云文件夹；名称相同的两个本地文件夹不是同一共享目录。
4. 按当前界面选目标游戏执行 Sync，查看实际上传/下载状态及冲突选择。不要只凭文件夹授权成功就报告云同步成功。
5. 在设备 A 正常保存一次可识别的进度并同步；待云文件可用后在 B 同步，打开游戏检查。随后用 B 的新进度做 B→A 测试。每一步记录版本、时间、方向和实际读档结果，不记录账号或真实设备标识。
6. 用户需要冲突/回滚验收时，再用测试进度制造分叉并核对冲突选择、历史恢复结果。选择保留哪份存档由用户决定，不对真实存档自动覆盖。

同步失败保留本地游戏数据、备份和原始错误，先核对云目录、授权、占位文件下载及版本，不删除快照或重置云目录。教程只演示已经实际验证的步骤。

## 源码入口与历史说明

读取基础仓 `LiveContainer/docs/save-sync-usage.md`、`LiveContainer/docs/save-sync-design.md` 和 `LiveContainer/LiveContainerSwiftUI/SaveSync/` 理解当前实现。功能提交 `7930cdf` 中已将构建示例改为相对目录，并移除固定设备签名身份；仍需按当前工作区和每台设备的实际身份解析路径与安装目标。

宿主复建使用本 Skill 的 [构建文档](livecontainer-build.md)，产物位于 `LCRebuild/build/`。共享发布前需将功能及对应文档提交到子仓，再更新基础仓指针；具体见 [发布检查](runbook.md#发布给其他人之前)。
