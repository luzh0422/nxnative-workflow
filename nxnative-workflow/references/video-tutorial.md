# 茶杯头 Switch → iPad：10–12 分钟录屏教程

交付形式：可直接录制的口播、分镜和剪辑说明；本文件不代表已录制或已生成视频。面向普通玩家，以本仓库已经跑通的 Cuphead 1.3.7 为案例，成片目标约 **11 分 45 秒**。实际演示版本与证据见 [验证基线](validated-baseline.md)，执行步骤见 [端到端流程](runbook.md)。

## 讲解主线与录制准备

先展示 iPad 上的结果，再解释两个 IPA，随后沿「电脑准备 → 安装宿主 → 配置续签与证书 → 导入游戏 → 真机验证」推进。普通玩家先理解每一步的用途，具体编译命令放说明区，屏幕上只保留正在操作的一条。

第一次出现时，用一句话解释工具：nxnative 负责游戏适配与构建；LiveContainer 是设备上的运行宿主；SideStore 负责签名续期；Impactor 是 Mac 上的安装工具；idevice_pair 生成当前设备的配对文件。避免把所有工具堆在开头介绍。

录制前准备：

- Mac 横屏录制，放大终端字体和光标；iPad 画面作为独立素材，按章节切换，不长期缩在角落。使用现有录屏工具即可，先试录 15 秒检查麦克风、设备声音和文字可读性。
- 开启勿扰，关闭无关窗口。剪辑遮住账号、通知、设备序列号/UDID、Team、私人路径、证书、配对和密钥内容。演示输入只显示文件名，不打开敏感文件。
- 使用现有可用环境和已经生成的 IPA。录制讲解不需要重装全部工具、关闭再开启开发者模式、重置证书或重新生成有效配对。无法重演的步骤显示当前状态并标注「首次设置时执行」。
- 备好本机真实构建日志、校验报告和成功画面；耗时段标注「已加速/等待省略」。补录镜头标为补录，不拼接成一次连续操作的假象。
- 本机 Save Sync 已形成提交 `7930cdf`，尚未推送远程。对外发布前完成 [发布检查](runbook.md#发布给其他人之前)，并在视频说明写明使用的基础仓和子仓提交。

下文「口播」可直接照读；操作间留 3–8 秒让观众看清。每章按目标时长剪辑，编译、USB 复制和设备重启的实际等待不计入讲解时长。

## 00:25–01:10｜两个 IPA，先分清用途

**画面与操作**：用 [流程图](runbook.md) 改成适合屏幕的两列：左侧游戏输入 → nxnative → Cuphead.ipa；右侧 LiveContainer 源码 + 基础合并包 → 宿主 IPA → Impactor。两条线最后连到 iPad 的 LiveContainer。

**口播**：

## 06:00–07:15｜开发者模式与 Remote Pairing

**画面与操作**：先录 iPad **设置 → 隐私与安全 → 开发者模式**。首次设置才展示开启、重启和确认。切回 Mac 的官方 idevice_pair：选择 USB 设备 → Remote pairing → Create → Validate → Save to file…。保存对话框只留脱敏文件名。

**口播**：

> 宿主安装后，先确认设备开发者模式已经开启。入口在设置、隐私与安全、开发者模式。第一次开启需要重启，并在重启后再次确认。已经开启的设备直接检查状态就行。
>
> 接下来准备 SideStore 使用的配对文件。这里用官方 idevice_pair 的 macOS 版本。USB 连接当前 iPad，保持解锁，在设备上信任这台电脑。
>
> 工具里选择这台 USB 设备，配对类型选 Remote pairing，再点击 Create。生成后一定点击 Validate，验证成功才保存为 plist 文件。普通的 Lockdown 配对文件不能只改个名字就拿来替代。
>
> 这个文件属于当前设备。把它传到同一台 iPad 的文件 App，后面在 SideStore 里导入。已经有当前设备的有效文件，可以先验证再复用，不需要每次重新生成。

**字幕/剪辑**：「开发者模式：重启后确认」「Remote pairing → Validate → 保存」「配对内容不展示」。设备选择器遮住 UDID 和真实设备名，使用“演示 iPad”别名。

## 07:15–08:10｜SideStore 导入与续签

**画面与操作**：iPad 内置 SideStore 依次打开 **Settings → Pairing File Management → Remote Pairing File → Import / Replace File**，选文件后 **Activate**、**Set as Preferred**；停留展示 Active/Preferred 均为 `rppairing`。展示 `idevice` 后端、LocalDevVPN 连接，再展示重开 LiveContainer 后的 Refresh All 结果。

**口播**：

> 在 LiveContainer 内置的 SideStore 中，进入设置和配对文件管理，找到 Remote Pairing File，导入刚才验证过的文件。
>
> 导入以后还要激活，并设为首选。检查 Active 和 Preferred 这两项，都显示 rppairing。接着保持 idevice 后端，连接 LocalDevVPN，完全退出再打开 LiveContainer，然后执行 Refresh All。
>
> 我们看实际成功提示和更新后的有效期。出现错误就停在这个环节，先核对文件是否属于这台设备、有没有验证通过、后端和 VPN 是否正确。续签成功以后，还有一个启动游戏前的证书设置要做。

**字幕/剪辑**：「Active = Preferred = rppairing」「idevice + LocalDevVPN」「以实际刷新结果为准」。有效期局部放大；账号整栏遮罩。菜单标签按录制所用版本核对。

## 08:10–09:00｜关键补充：导入 JIT License

**画面与操作**：若有当时错误截图，展示 `JITLess mode is required since iOS 26`，标注“本次遇到的问题”。没有截图则用文字卡引用，不伪造系统弹窗。进入 LiveContainer **Settings → JIT-less → Import Certificate from SideStore**，确认导入，再做 **JIT-Less Mode Diagnose → Test JIT-Less Mode**。

**口播**：

> 这是我们这次实际卡住的地方：游戏已经导入，启动时却提示 iOS 26 需要 JITLess。后来在 LiveContainer 中导入 JIT License，才解决了这个启动提示。
>
> 对应操作是进入 LiveContainer 设置，在 JIT-less 中点击 Import Certificate from SideStore，确认导入，再运行 JIT-Less Mode Diagnose 里的测试。
>
> 开发者模式、配对文件、续签和这里的证书导入，各自解决不同的问题，都要看自己的检查结果。若提示找不到证书，先检查 SideStore 的登录和 Refresh All，再回来导入。

**字幕/剪辑**：「首次运行前：导入证书 + JIT-less 测试」。诊断通过的画面只有实测后才能使用；不要把“已点击导入”剪成“测试通过”。
